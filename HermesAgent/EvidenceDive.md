# Evidence Dive

Use this skill when ONE target or question has already been selected.

## Goal

Build the strongest evidence chain possible, not the longest report.

## Method

1. Define the exact question and what evidence would change the conclusion.
2. Build a dated timeline from first signal to current state.
3. Map relevant actors: team, investors, partners, users, developers, competitors, regulators, wallets/contracts when applicable.
4. Follow the money/data: funding, revenue, fees, incentives, users, volume, traffic, pricing, treasury, token supply, transfers or other measurable data.
5. Inspect technical evidence when relevant: repositories, commits, releases, deployments, frontend/API changes, docs and contracts.
6. Search for contradictions between claims and observable evidence.
7. Once a likely thesis forms, actively search for evidence that would invalidate it.

## Evidence labels

### CONFIRMED
Directly supported by primary or highly reliable evidence.

### STRONG INFERENCE
Multiple facts support the interpretation but there is no direct confirmation.

### UNCONFIRMED
Potentially relevant claim that could not be independently verified.

### CONTRADICTED
Available evidence directly conflicts with the claim.

## Final report

Always include:

1. Main conclusion.
2. Timeline.
3. Strongest evidence.
4. Important numbers/data.
5. Contradictions or alternative explanations.
6. What remains unknown.
7. What would change the conclusion.
8. Primary sources.

If maximum depth is requested, do not compress meaningful evidence.
